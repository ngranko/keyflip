# Detect from-source from the text; follow even when nothing changed

Conversion direction is not “current input source → the other of the pair.” The extra counts **votes** (a character votes for a source only if it inverts there and not on the other), takes the winner as from-source, and rewrites toward the other member. Ties use the current source when it is in the pair; otherwise the trigger is a no-op.

Unmapped characters, Option-only characters, and dead-key-only letters are left unchanged — but a character is only unmapped once **substituted punctuation has been folded back to the key that produced it**. macOS replaces straight quotes as you type, so an apostrophe struck on the `'`/`э` key arrives as U+2019, which is on no layout at all: the unmapped rule caught it and `этот` came back as `’тот`. The four smart quotes fold to `'` and `"` before the lookup, and a direct hit always wins, so nothing genuinely on a key is affected. Only quotes fold. An em dash would land on the hyphen key and quietly turn punctuation the user chose into punctuation they did not, which is the unmapped rule doing its job. Invert uses unshifted and Shift only; simplest physical key on collisions inside that set. Follow selects the destination whenever conversion ran, including when no character changed, and does not try to cooperate with per-document input-source switching.

The obvious alternative — always convert from the currently selected source — fails on a selection typed earlier, after the user has already followed or switched by hand.
